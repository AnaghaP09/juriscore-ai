Two features, one platform

Apply the same policy before and after AI.

Veil and Plumb are JurisCore features. They share a policy library, verdicts, evidence references, review controls, and audit receipts.

Veil

Protect what goes in

Detect and transform configured sensitive information — PII, credentials, secrets, tenant identifiers, prompt attacks — before it reaches an AI model, then expose a reviewable transformation receipt.

Plumb

Prove what comes out

Compare documentation and product assertions with code, configuration, schemas, and APIs. Return matches, drift, or cannot determine — each with citations.

Quickstart

Three commands to a running instance.

Download the release package, install one toolchain — Bun — and start it. Every dependency is already inside the package, so starting it installs nothing and reaches no registry. Works on macOS, Linux, and Windows. 

# 1 · install Bun (macOS + Linux; Windows uses the PowerShell line in RUN.md)
curl -fsSL https://bun.sh/install | bash

# 2 · unzip the release package
unzip juriscore-0.1.0.zip
cd juriscore-0.1.0

# 3 · start it (Windows: start.cmd)
./start.sh
  ➜ Listening on: http://localhost:8080/

# the deterministic checks, from a source checkout
bun run check:core
  ✔ Contracts  verdict + evidence checks passed
  ✔ Veil       input protection checks passed
  ✔ Plumb      source-of-truth checks passed
  ✔ MCP        tool boundary checks passed
  ✔ Receipts   receipt checks passed

The checks are deterministic and run headless, so they drop into CI. They are the gate every release package is built behind. There is no juriscore command-line program: the checks run through bun run check:* in a source checkout, and the package ships the app.

How it works

One validation contract around every model.

The application selects the policy. JurisCore returns a verdict, findings, and evidence.

  1. 01

    Screen the input

    Apply the selected policy before content reaches the model. Detect sensitive categories, secrets, and prompt attacks.

  2. 02

    Transform or block

    Redact or tokenize prohibited values, preserve permitted context, and stop the request when policy requires it.

  3. 03

    Validate the assertion

    Compare material claims with the authoritative source. Return matches, drift, or cannot determine with references.

  4. 04

    Keep the receipt

    Return a structured verdict and evidence record that the application can review, store, or enforce.
