# Fix the Use Case drill-down page

## What "Drill down" is meant to do
On `/dashboard/use-cases`, each card's **Drill down** link opens `/dashboard/use-cases/$key` — a detail view for that one AI use case. It should show:
- Key metrics (volume, block rate, citation coverage, avg latency)
- Persona / capability / value / risk profile cards
- Verdict mix (allowed / revised / blocked bars)
- Top failure modes
- Recent audit entries table
- CSV + PDF export

## Why it looks empty/broken today
The route works and navigates correctly, but the page renders sparse content because:

1. **Plumb-drift has near-zero data.** Audit entries are generated by picking a random use case from `USE_CASES` and only include finance/healthcare sample prompts. `plumb-drift` gets ~1/7 of 512 rows *on average* but with the seeded RNG can land very low, and its prompts/reasons are compliance-oriented, not code-vs-docs. So the verdict bars, top failure modes, and audit table look meaningless for the flagship "Plumb" wedge.
2. **No empty state.** When `entries.length === 0` (or very low), MetricCard shows `0ms`, VerdictBars render as flat rails, "Top failure modes" shows "No blocked or revised entries", and the audit table body is blank — the page silently degrades instead of explaining anything.
3. **PageHeader stats crowd the eyebrow row.** Three badges (domain, regulatory driver, "Plumb wedge") wrap awkwardly at ~1080px, making the header look broken.
4. **Recent audit table overflows** on narrower widths; the ID + timestamp columns don't truncate, so on the current viewport rows can appear cut off.

## Proposed changes (scope: `src/routes/dashboard.use-cases.$key.tsx` + mock data)

### 1. Give every use case real data
In `src/lib/juriscore/mock.ts`:
- Guarantee a minimum audit volume per use case (e.g. round-robin seed of ~40 entries per key *before* the random 512, so every use case has a solid sample).
- Add Plumb-specific sample prompts (`"Judge README claim against fees.ts diff"`, etc.) and Plumb-specific reasons (`"Prose claim contradicts code"`, `"Stale infra doc"`, `"Sales deck cites removed SKU"`) so the drill-down for `plumb-drift` reads coherently.

### 2. Add real empty / low-data states in the drill-down
- If `entries.length === 0`: replace metric grid, verdict card, failure-mode card, and audit table with a single friendly panel ("No audit activity yet for this use case") plus a "Back to use cases" action.
- If `entries.length < 10`: show a subtle "Low sample size — metrics may not be representative" note above the metrics grid.

### 3. Tighten the drill-down layout
- Move the export buttons and back-link into a single sticky header row that doesn't wrap awkwardly.
- Collapse the eyebrow badges into one line with `flex-wrap` + smaller gap; drop the redundant domain badge (it's already in the metrics context).
- Make the audit table horizontally scrollable inside a `min-w-0` wrapper and truncate the ID column with `font-mono text-xs truncate max-w-[10ch]`.
- On `md` and below, stack the verdict-mix + top-failure cards vertically instead of the current `lg:grid-cols-3` (which currently squeezes them).

### 4. Add loading + error affordances
- The route already has `notFoundComponent`; add a small `errorComponent` so any future loader failure shows a retry instead of a blank frame.

## Out of scope
- No changes to governance routes, sidebar, other dashboard surfaces, or backend.
- No new dependencies.
